# Desktop User Testing Analysis Report
**Study Date:** October 7, 2025
**Total Participants:** 10
**Variants Tested:** Coffee (Scenario 1) and Mars (Scenario 2)

---

## Executive Summary

This report analyzes feedback from 10 desktop users testing Wikipedia's content suggestion features across two prototypes. The study revealed strong user interest in the suggestion feature, with critical insights about customization needs, communication gaps, and design preferences.

---

## Key Findings

### 1. **Feature Clarity & Understanding**

**Positive Feedback:**
- Majority found the feature **"very clear"** or **"somewhat clear"** in what it does
- Users quickly understood the purpose: suggesting content additions to Wikipedia
- Interface was intuitive and easy to navigate

**Concerns:**
- **Major gap:** Unclear what happens AFTER submitting suggestions
  - Who receives them? (Wikipedia team? Community editors? AI?)
  - What's the timeline for implementation?
  - Will users be notified when content is added?
- Uncertainty about the editorial process and verification mechanisms

**Quote (Transcription 31):**
> "It's been sent to the team, but I don't know what that means. I don't know who that means, I don't know the timescales, I don't know what action needs to be taken. I don't know if I'll be notified."

---

### 2. **Critical Need: Custom Input Option**

**Finding:** The most consistent and urgent request across participants

**Problem:**
- Preset menu options feel **limiting**
- Users want specific information not available in dropdown
- Unable to request niche or detailed topics

**User Requests:**
- Free-text field to write custom suggestions
- Ability to specify exact missing information
- More flexibility beyond pre-generated options

**Quotes:**
- (Transcription 25): *"Maybe I should be able to add custom solution... whatever suggestions that Wikipedia is providing may not be my requirement"*
- (Transcription 28): *"Maybe the fact that you are kind of making me order from a preset menu, maybe there would be an ability for me to have an open format"*
- (Transcription 34): *"I would want more freedom to really write a sentence or two about what exactly I want to see"*

**Impact:** Multiple users rated the feature lower specifically due to lack of custom input

---

### 3. **Scenario Comparison: Coffee vs. Mars**

#### **Scenario 1 (Coffee) - Topic-Based Suggestions**
**Strengths:**
- Broader topic options (Cultivation, Bean Varieties, Brewing Methods, Culture)
- Users appreciated comprehensive choices
- Better for short articles lacking entire sections

**Weaknesses:**
- Limited to pre-set categories
- No option to request specific details within topics

#### **Scenario 2 (Mars) - Section-Based Suggestions**
**Strengths:**
- Contextual suggestions per section
- Options for format (more details, pictures, examples)
- Users liked section-specific targeting

**Weaknesses:**
- **Too vague** - "more details" doesn't specify what details
- **Limited granularity** - can't request specific information
- Risk of editors adding content user didn't want

**Quote (Transcription 32):**
> "The options to improve are very limited because it only says more details, examples or pictures... I would say like physical realistic. OK, talk about this thing. Be more specific."

**User Preference:** Mix both approaches - topic selection + custom text field

---

### 4. **Trust & Confidence Levels**

**High Trust in Wikipedia Overall:**
- Users expressed strong confidence in Wikipedia's verification process
- Trust in community editorial standards
- Faith in fact-checking mechanisms

**Low Trust in Feature Impact:**
- Only **30-50% confidence** suggestions would lead to improvements
- Concerns about:
  - Response time (could take "months or years")
  - Whether suggestions get ignored
  - Lack of feedback loop

**Quote (Transcription 34):**
> "I would say 30, 40, maybe 50% at most. Confident about that... if we're in a more niche or obscure page... I don't think that it will happen so soon."

---

### 5. **Perceived Usefulness**

**Overall Rating:** **Moderately to Very Useful**

**Why Users Find It Useful:**
- Low-effort way to contribute without editing
- Helps prioritize what content Wikipedia should develop
- Addresses frustration with incomplete articles
- Good for people who lack time/expertise to edit directly

**Barriers to Higher Rating:**
1. No immediate value (doesn't provide the information now)
2. Uncertain timeline for implementation
3. Lack of custom input option
4. No confirmation or tracking system

**Quote (Transcription 31):**
> "I think it's slightly useful... it doesn't give you the information, so you can request it, but it's not as if you've got the information then after you request it."

---

### 6. **User Mental Models**

**What Users Think Happens:**
1. Suggestions go to Wikipedia administrators/editors
2. Data gets aggregated to show popular requests
3. Editors prioritize high-demand topics
4. Content gets created by volunteer editors or possibly AI
5. Some form of verification/approval process

**Who Users Think It's For:**
- General Wikipedia readers who want more content
- Curious learners seeking deeper information
- People who lack expertise/time to edit themselves
- Way to democratize content direction

**Design Expectations:**
- Point system or incentives for editors
- Ranking/voting mechanism for popular requests
- Some editors specialize in responding to requests

---

### 7. **Feature vs. Direct Editing**

**Strong Preference for Suggesting Over Editing:**

**Reasons:**
- **Lack of expertise:** "Unless I'm an expert, I don't think I should edit"
- **Time constraints:** Editing requires research, proper sourcing, following Wikipedia rules
- **Lower barrier:** Suggesting is quick and easy
- **Comfort level:** Less intimidating than editing

**Quote (Transcription 27):**
> "I think the suggesting would be better. I don't think that anybody should be able to go in there and just edit it unless it's being monitored. I think that suggestions for content is a better option."

**When Users Would Edit:**
- If they have direct expertise on the topic
- For small corrections they're certain about
- If they have time to follow Wikipedia's editorial process

---

### 8. **Critical Missing Features**

Based on user feedback, the feature needs:

#### **A. Transparency & Communication**
- **Timeline estimates** per request type
  - Example: "Pictures: 10 weeks, Text: 5 days"
- **Status tracking:** See if suggestion was accepted/rejected/implemented
- **Notification system:** Alert when requested content is added
- **Progress indicators:** Show how many people requested same topic

**Quote (Transcription 31):**
> "I would say give a timeline within that suggestion... Come back and check, rather than just letting it suggest and then disappear."

#### **B. Customization**
- **Free-text field** for specific requests
- **Hybrid approach:** Preset options + custom input
- **More granular options** within each category

#### **C. Context & Guidance**
- Explain the editorial process
- Show what makes a good suggestion
- Display statistics (e.g., "47 people requested this topic")

---

### 9. **Language & Cultural Considerations**

**Note:** Transcription 30 was in Spanish - user expressed:
- Trust in Wikipedia ("nunca me ha fallado")
- Preference for suggesting over editing (risk of confusion)
- Desire for more detailed options

**Implication:** Feature should support multilingual use cases

---

### 10. **Unexpected Insights**

#### **Too Much Information Problem**
- One user (Transcription 33) mentioned Wikipedia articles being **too long**
- Wished for better search-within-page functionality on mobile
- Suggests need for content summarization, not just expansion

#### **Visual Content Priority**
- Multiple users specifically requested **more pictures and diagrams**
- Visual learners want graphical representations
- Media-rich content valued highly

#### **AI Integration Expectations**
- Users speculated about AI involvement
- Some hoped AI could auto-generate requested content
- Concern about maintaining Wikipedia's human-curated quality

#### **Comparison Features**
- User wanted comparative articles (e.g., "Mars vs. Earth")
- Cross-topic analysis valued

## User Profiles & Patterns

### **The Knowledgeable Contributor**
- Has expertise but lacks time to edit
- Wants to guide content direction
- Expects editorial validation

### **The Curious Learner**
- Finds gaps while researching
- Wants deeper dives on specific aspects
- Values comprehensive information

### **The Frustrated Seeker**
- Has experienced incomplete articles
- Usually leaves Wikipedia to find answers elsewhere
- Would use suggestions to improve future searches

### **The Casual Reader**
- Appreciates Wikipedia as-is
- Would suggest if process is effortless
- Needs clear value proposition

## Recommendations

### **Immediate Priorities (P0)**

1. **Add Custom Text Input Field**
   - Critical for user satisfaction
   - Most requested feature across all participants
   - Implementation: Add optional free-text area below preset options

2. **Clarify Post-Submission Process**
   - Add confirmation message explaining next steps
   - Show who handles suggestions (e.g., "This will be reviewed by Wikipedia editors")
   - Set expectations for timeline

3. **Combine Both Prototypes**
   - Use section-based suggestions (Mars model)
   - Include broader topic additions (Coffee model)
   - Allow custom text for all options

### **High Priority (P1)**

4. **Add Status Tracking**
   - Let users see if their suggestion was:
     - Received
     - Under review
     - Accepted/Implemented
     - Declined (with reason)

5. **Show Popularity Metrics**
   - Display "X people requested this"
   - Help users see they're not alone
   - Motivate editors with demand data

6. **Improve "More Details" Options**
   - Replace vague "more details" with:
     - Specific types (historical background, scientific explanation, etc.)
     - Word count indication (brief vs. comprehensive)
     - Content type (text, images, videos, charts)

### **Medium Priority (P2)**

7. **Add Timeline Estimates**
   - Show expected fulfillment time per request type
   - Manage expectations realistically
   - Explain factors affecting speed

8. **Create Notification System**
   - Email/account notification when content is added
   - Link back to updated article
   - Thank contributors

9. **Provide Editor Incentives**
   - Gamification elements for editors responding to requests
   - Leaderboards or recognition system
   - Priority queue for high-demand topics

### **Future Enhancements (P3)**

10. **Visual Content Pipeline**
    - Streamlined process for image requests
    - Integration with Wikimedia Commons
    - AI-assisted diagram generation

11. **Cross-Language Support**
    - Ensure feature works globally
    - Translation of suggestions
    - Cultural context consideration

12. **AI-Assisted Suggestions**
    - Use AI to suggest what topics might be missing
    - Auto-generate initial drafts for editor review
    - Maintain human oversight

## Risk Analysis

### **Risks of Current Design:**
1. **User abandonment** due to lack of feedback
2. **Duplicate suggestions** without aggregation
3. **Editor overwhelm** if requests aren't prioritized
4. **Disappointment** when expectations aren't met
5. **Spam or low-quality requests** without filtering

### **Mitigation Strategies:**
- Implement request aggregation and voting
- Show real-time stats to set expectations
- Add spam filters and request validation
- Provide clear editorial guidelines
- Create editor workflow tools for managing requests

---

## Success Metrics to Track

### **User Engagement:**
- Number of suggestions submitted per session
- Return rate of users who submitted suggestions
- Suggestion completion rate (started vs. submitted)

### **Content Impact:**
- % of suggestions that lead to article updates
- Time from suggestion to implementation
- User satisfaction with implemented changes

### **Trust & Confidence:**
- User ratings of suggestion feature
- % of users who would recommend feature
- Repeat usage rate

---

## Conclusion

The content suggestion feature shows strong potential to bridge the gap between casual readers and Wikipedia's editing community. Users appreciate the low-barrier way to contribute, but critical improvements are needed:

1. **Custom input is non-negotiable** - Users need flexibility beyond preset menus
2. **Transparency builds trust** - Clear communication about process and timelines
3. **Feedback loops matter** - Users want to know their suggestions made a difference
4. **Combine best of both** - Use section-based + topic-based + custom text

**Overall Sentiment:** Positive with significant room for improvement. Users see value but need assurance their effort won't disappear into a void.
